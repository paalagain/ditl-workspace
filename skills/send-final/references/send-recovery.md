# Send recovery

Revision: 7

Read [Project](project.md) and [Format](format.md). Apply this protocol at the beginning of either send and after every uncertain filesystem or remote result. Saved phase/status booleans are hints. Match actual files and actual transport observations before deciding what remains.

Before fresh selection, inspect the pending record's `captureReplacement`. A saved intent resumes through Format's `resumeCaptureReplacement` with fresh complete repository-bound observations. For an explicit user request to deliver a repaired numbered version before packaging, call `beginCaptureReplacement(root,deliveryId,{versionNumber,explicitDesignerStatement},observation)` then resume it. Observation is `{repositoryId,complete:true,releases,tags}` from complete current listings. Ordinary retry uses the saved capture.

The transition retains the UUID/tag and reservation ledger, journals the selected version and its complete expected inventory before copying, and archives the original record, snapshot and evidence under `capture-history/<operationId>/`. It promotes only a verified complete replacement, preserves source versions, marker and checklist, and then requires fresh portability, reassessment and completion evidence. Any saved manifest, ZIP, descriptor, release notes, package/remote identity or attempted draft prevents replacement. A draft, publication or occupied tag in fresh remote observations also prevents it. Resume the same intent after a completed copy or interrupted promotion. A partial or changed copy remains evidence for explicit reconciliation; never overwrite it with newer source bytes.

## Locate the operation

Use [Observed cancellation](cancellation.md) for the common application/report owner. Establish actual matching publication before processing a saved operation's cancellation: a verified published final resumes completed closure/bookkeeping and leaves later requests for Inbox; a verified published nonfinal stands and completes its own bookkeeping. For unpublished operations, apply observed requests/hand closure before any fresh capture or publication. Preserve all pending captures, exact packages and drafts when refusing. Reconcile cancellation's saved plan/application/disclosure records across interruption, comparing the captured activation token rather than clearing a later assignment.

Scan `.designeritl/pending/` as well as the pending index. Use Format's `validatePendingRecord(exactBytes, repositoryId)` to validate version 1 records, including the numbered version or file selection. The directory basename must equal its delivery UUID, and its snapshot path must resolve inside that operation. Preserve and report malformed or unknown records. Reconcile Project's local mutation intent before changing records. Pending writes use Project's owner-record replacement, owner `deliveries`, the prior exact-byte hash (null only for a new record), and this validator on both preparation and recovery.

A completion entry plus actual matching published descriptor/asset, verified local package and required closed issue establish retained completed history. Confirm the UUID is absent from the pending index and a matching final activation is no longer assigned before skipping it. A phase marked complete alone does not. Inconsistent index/completion evidence is reconciled before a fresh transaction. More than one unfinished operation requires an explicit UUID choice; invoking a different send command does not change a saved operation's kind or tag.

For a complete package, call `verifyPendingDelivery(pendingRoot, config.repository.repositoryId)` from the verbatim Format snippet. It reads `record.json`, `descriptor.json`, `manifest.json`, `delivery.zip`, the snapshot and exact final evidence files. Record `assignmentToken` retains the captured repository/order and activation UUID. `stagingPath` is exactly this operation's snapshot path. Retry uses that snapshot and exact ZIP. Verify saved hashes and size, manifest identities, evidence bindings and complete captured structure before remote mutation and again immediately before publication.

If capture is incomplete, preserve partial staging and record where interruption occurred. An existing verified capture may be assessed and packaged without copying the editable source again. For a file delivery, compare `inventoryDelivery(stagingPath, 'files')` with the entire saved `selectedInventory`, including directories. If they agree, save the verified capture fields and continue.

Otherwise obtain an explicit choice to retain that operation's partial snapshot under `capture-failures/` and retry capture under the same UUID/tag. For files, retry uses the saved selection and expected inventory. If source bytes or paths have changed, preview the new explicit selection with `inspectFileSelection`, show it to the designer and obtain approval. With the partial snapshot retained elsewhere, call `reselectFiles(root, deliveryId, {...preview, deliveryNote, explicitDesignerStatement}, observation)` with a note for the new selection. Capture from the returned record. Reselection requires the incomplete capture, an absent snapshot, and no package or remote attempt. A numbered prototype retry requires fresh portability and any applicable final evidence.

## Establish remote identity

Use complete, explicitly repository-targeted paginated listings of issues, releases (including drafts), release assets and tags. For example, `gh api --paginate --slurp 'repos/OWNER/NAME/releases?per_page=100'` and the corresponding tags/issues/assets endpoint. Flatten only after every page succeeds. An error, truncated response or unknown issue status stops consequential work; it is not an empty lookup or an open order. Preserve observations, exact descriptors, release/asset IDs, timestamps and failed requests under this pending operation.

Parse exactly one `designeritl-delivery` JSON descriptor in a delivery-like release. Compare the complete saved descriptor, UUID, tag and repository/order/kind. Human prose cannot establish ownership. The same UUID under another tag, multiple matching releases, an occupied tag with another/malformed identity, or a tag with no evidence tying it to this delivery is a conflict. Never acquire another tag or renumber on retry. New nonfinal allocation accounts for all tags/releases/drafts and local reservations; retry uses its existing reservation.

| Independently observed evidence | Resume action |
| --- | --- |
| Verified local package; complete lookup finds no matching release or occupied tag | Apply the durable draft creation guard below. Only a fresh proven-never-submitted reservation or an independently proven non-dispatch can begin a create. An unresolved attempt or missing legacy marker stays read-only despite complete empty listings. |
| Receipt-backed direct read matches an owned draft absent from complete listings | `resume-unlisted` permits asset verification/upload by release ID only. Report `Draft RELEASE_ID exists but is not yet listed by GitHub; rerun later`. Publication waits for a complete listing containing exactly this release with no duplicate in the union. |
| Matching owned draft; asset absent | Upload the saved `delivery.zip` to its release ID. On uncertain upload, list assets and download any matching filename before deciding whether upload remains necessary. |
| Matching owned draft; single expected asset exists | Download into new verification staging. Compare exact size, ZIP hash, manifest hash/identity and full inventory. Reuse matching bytes and retain their asset ID. |
| Owned draft asset differs or is partial | Preserve downloaded bad bytes and observations. Ask for deliberate repair naming this draft/asset. Only after that choice, re-read ownership and unpublished status, delete only the proven-owned bad asset ID, upload the saved ZIP and verify again. No blind clobber, foreign asset removal or published mutation. |
| Verified draft; unique exact identity in complete listings; issue open and no cancellation observed at the last pre-publication check | Require `requireDraftPublication` for this release ID, reverify local package and frozen evidence, publish this draft, then read actual published metadata and download/verify its asset. |
| Publish response lost | Read the saved identity. If published, verify the published descriptor and asset; continue completion. Do not create, upload or change notes. |
| Matching published nonfinal | Verify exact published artifact, then reconcile completion bookkeeping. Do not close the issue or change the current assignment/working marker. |
| Matching published final; issue open | Verify exact published artifact, then close as completed and read back closed status. Retry closure only; do not repeat capture, assessment, acknowledgment or upload. |
| Matching published final; issue closed | Verify exact published artifact, then reconcile bookkeeping, regardless of who closed the issue. Do not reopen it or reinterpret it as cancellation. Leave open cancellation requests for inbox to report after final delivery. |
| Closure succeeded; bookkeeping interrupted | Re-read the entire current state. Add/reconcile this completion entry, remove only this pending UUID, and compare-and-clear only its captured final assignment token. A later activation, including the same order with a new UUID, remains selected. |
| Cancellation or hand closure observed before publication | Refuse publication and apply the observed-cancellation policy. Preserve any draft, capture, ZIP, checklist and prototype; no release is withdrawn. A request observed after publication does not invalidate a published delivery. |
| Corrupt local package/record, incompatible format, identity/hash conflict, missing lookup pages or unknown status | Preserve evidence and stop without a completion claim. Restore original bytes only through an explicit recovery from the same matching remote asset when saved exact hashes prove them. Never repackage newer source to conceal corruption. |

After each remote request, success is established by read-back and exact artifact verification, not the command's exit code. An unavailable verification download is still pending. Re-read the issue immediately before publication; an existing draft never bypasses this gate. Before retrying a final order closure, use Delivery's fresh `observedOrderIssues` / `orderIssueProblem` guard as well: a malformed issue or relation stops only that order's closure and is never modified. Retain its pending evidence, report the number/reason and continue independent orders. Global observation/identity/local-state failures still stop globally. After verified publication, do not edit or delete the release even if a later request crosses it.

## Guard draft creation

GitHub permits multiple unpublished releases with the same tag, including identical POST payloads. Release-by-tag can return 404 for an existing draft. Complete release listings can lag creation. Neither absence nor a failed command proves that a create failed to reach GitHub.

New `Sending.reserve` records contain `draftCreation: {schemaVersion:1, attempts:[]}` from their original local reservation. Retain this history through capture, fixes, packaging and completion. A missing marker on an older record means unknown submission history: preserve the original record and reconcile read-only. Never initialize an empty history on an existing record, remove attempts, reset flags, allocate another UUID/tag, or create a replacement to escape uncertainty.

1. Verify the exact saved package with `verifyPendingDelivery`, including retained create receipt bytes. Save raw successful REST pages with `gh api --paginate --slurp 'repos/OWNER/NAME/releases?per_page=100' > REST_PAGES`. Also save complete GraphQL releases, including drafts, with `gh api graphql --paginate --slurp -f owner=OWNER -f name=NAME -f query='query($owner: String!, $name: String!, $endCursor: String) { repository(owner: $owner, name: $name) { releases(first: 100, after: $endCursor) { nodes { databaseId tagName isDraft description } pageInfo { hasNextPage endCursor } } } }' > GRAPHQL_PAGES`. Save complete tags with `gh api --paginate --slurp 'repos/OWNER/NAME/tags?per_page=100' > TAG_PAGES`. Preserve page boundaries. Normalize each GraphQL page's `data.repository.releases.nodes` to `{id:databaseId,tag_name:tagName,draft:isDraft,body:description}`. Require successful completion of every page, no GraphQL errors or null repository/connection/nodes, and final `hasNextPage:false` before setting its completeness flag. Pass REST pages, its actual completeness flag, flattened complete tags and `{graphql:{pages:normalizedGraphqlPages,complete:graphqlComplete}}` to `reconcileDraftCreation(record, descriptor, pages, complete, tags, observations)`. Every provided source must be complete. Existing REST-only callers may omit `observations`. Conflict detection uses the union, deduplicated by release ID; conflicting observations of the same ID also stop. Malformed/incomplete observations, occupied tags, conflicting descriptors or duplicate matching IDs stop the action. A unique exact UUID/tag/full-descriptor match in either listing returns `{action:'resume',releaseId,draft}`, even for a legacy record. Continue only with that release ID and verified unpublished/published status.
2. For a returned create candidate, recheck order and cancellations, then call `beginDraftCreation(projectRoot, deliveryId, pages, complete, tags, observations)` immediately before the single draft-create request. This verifies the unchanged saved package, rereads prior proof bytes, and journals one `{attemptId,descriptorSha256,startedAt,nonDispatchProof:null}` through Project. Wait for completed replacement and reread before dispatch. Save UTF-8 JSON at `REQUEST_JSON` with `tag_name` equal to the saved tag, `draft:true`, `name` equal to the existing title and `body` equal to the exact saved release notes containing the descriptor. Use `gh api --method POST repos/OWNER/NAME/releases --input REQUEST_JSON > .designeritl/pending/UUID/evidence/draft-create-ATTEMPT_UUID.json`. Create the evidence directory first and use a new attempt-specific output file. Retain the raw successful JSON response without rewriting it. Call `recordDraftCreateReceipt(projectRoot, deliveryId)` before continuing. It validates the returned positive release ID, tag, `draft:true`, and single parsed full descriptor against the saved package and attempt, then stores optional `createReceipt:{path,sha256,releaseId}` on that current attempt. The receipt is write-once, mutually exclusive with non-dispatch proof and retained permanently. The returned attempt permits exactly one request. A crash after the attempt is saved but before dispatch remains uncertain until independently proven otherwise. Never call the request again using that same attempt.
3. After any successful, failed, lost or unparseable response, reconcile fresh complete REST and GraphQL listings. A later empty lookup never restores create permission. Without a recorded receipt, an unresolved attempt still stops with `Uncertain draft create attempt; reconcile read-only and wait for identity`, even if a caller supplies an unbound direct read. With a receipt but no listed match, save `gh api repos/OWNER/NAME/releases/RELEASE_ID > DIRECT_RELEASE_JSON`, using only its receipt ID, and pass that parsed JSON as `observations.directRelease`. An exact ID/tag/full-descriptor match with `draft:true` returns `{action:'resume-unlisted',releaseId,draft:true}`. This permits asset verification/upload to that release ID while preserving the UUID/tag/ZIP. A mismatched direct read stops. If no direct read is supplied, stop with `Draft RELEASE_ID exists but is not yet listed by GitHub; rerun later`, substituting the receipt ID. Report that same message after permitted asset work while the draft remains unlisted. Use `gh api --paginate --slurp 'repos/OWNER/NAME/releases/RELEASE_ID/assets?per_page=100'` to list assets by ID, and `gh api --method POST 'https://uploads.github.com/repos/OWNER/NAME/releases/RELEASE_ID/assets?name=delivery.zip' -H 'Content-Type: application/zip' --input ZIP` only when the saved ZIP is absent. Download existing assets by asset ID into fresh verification staging with `gh api -H 'Accept: application/octet-stream' repos/OWNER/NAME/releases/assets/ASSET_ID > FRESH_ZIP`, then verify their exact bytes. Preserve the existing deliberate-repair rule for bad assets. Immediately before publication, obtain fresh complete listings, reverify the package, and call `requireDraftPublication(record, descriptor, pages, complete, tags, releaseId, observations)`. It requires a listed `resume` for exactly that unpublished release, with no duplicate/conflict across the union. A direct read or `resume-unlisted` never authorizes publication. Keep the issue/cancellation checks as well. When the release becomes listed, resume its same identity and verified assets without another create.
4. Safe non-dispatch needs an independent transport/tool observation for this exact attempt, rather than an agent's inference from an error code or absence. Preserve the original raw diagnostic as well. The observation producer writes exact JSON at `.designeritl/pending/UUID/evidence/draft-nondispatch-ATTEMPT_UUID.json` with exactly `schemaVersion:1, repositoryId, deliveryId, tag, attemptId, descriptorSha256, kind, requestDispatched, statusCode, observedAt` (UTC). Supported observations are `controlled-before-forward`, `spawn-not-started`, or `tool-not-executed` with `requestDispatched:false,statusCode:null`; or an actual authoritative HTTP rejection `kind:'http-rejected',requestDispatched:true,statusCode` in 400/401/403/404/405/409/410/422. A timeout, transport reset, generic nonzero status, barrier after an earlier uncertain create, or lost response is not such proof. Never fabricate this observation from a phase or saved intent. When the tool cannot independently establish non-dispatch, stay read-only.
5. Call `recordDraftNonDispatch(projectRoot,deliveryId)` only after that bound observation exists. It validates the exact file and stores its path/hash on the last attempt, preserving that attempt permanently. After a fresh complete identity lookup, a new `beginDraftCreation` rereads every proof and appends a new attempt under the same UUID/tag/package. Changed/missing proof, mismatched attempt/descriptor, or any unresolved earlier attempt refuses dispatch. The record replacement boundary also rejects history removal or reset. This retained-proof path is the only automatic retry of a previously attempted create.

The guard executes from the installed Format module. It adds no public command or separate shipped helper. Frozen evidence and captured/packaged bytes remain unchanged throughout these branches.

## Finish without losing later work

Record actual release/asset IDs and exact hashes through Project's verified replacement. A final clears assignment only when both `orderId` and `activationId` still equal the captured token; a different order or later activation remains intact. A nonfinal never clears assignment. State progress/checklist/versions belong to their owners and survive retries.

Persist/reconcile one `completedDeliveries` entry keyed by repository and delivery UUID, then remove only its UUID from the pending index. Verify actual state after replacement before marking the pending record complete. Keep the exact ZIP until publication, required closure and local bookkeeping are all independently confirmed; retain it after this workflow unless the user invokes later cleanup. Phase fields alone never authorize deletion or completion.
