# Verification strategy

The product seam is an explicit installed skill invocation followed by observable files, captured prototype behavior, work-order/release state and verified reception receipts. The central flow is `send-final` through developer `inbox`.

Maintainer tests execute canonical protocol blocks with real temporary filesystem trees and actual ZIP bytes. Cover complete agreed-task proof, exact evidence hashes, genuine completion decisions, unchecked-task acknowledgments, role configuration, archive paths/limits, coherent capture, explicit pre-package replacement, interrupted promotion, immutable package retries, cancellation and uncertain remote dispatch.

Build both role fixtures and Git-discoverable skills from canonical sources. Verify exact UTF-8/LF bytes, complete reference closures, revision/source hashes, role sets and explicit-only metadata. No generated copy is edited by hand.

Installed-host trials are opt-in and retain logs, commands, versions and evidence. Separate controlled transport/filesystem boundaries from actual private-service runs. Report only what was exercised; skipped trials and historical artifacts do not prove the revised product on an untested host or operating system.
