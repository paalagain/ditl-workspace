# Package workflows as Agent Skills

The product is a set of Agent Skills with shared instruction bodies across hosts; it has no compiled workflow CLI or OS-specific scripts, and each skill tells the agent which `gh` commands to run. This avoids binaries to sign, build per platform or keep in version lockstep between designer and developer. The cost is that behaviour depends on the agent following instructions, and installation needs Node and Git even though the designer never runs them.

A thin GitHub-runnable installation command asks for the local folder and role, then delegates platform selection, scope, platform-specific file adaptation and overwrite confirmation to Vercel's native skills CLI. It requires an interactive terminal and clears inherited agent auto-confirmation markers from the native child's environment so the human retains those choices.

The wrapper preflights the human guide before installation and writes it only after the native installer confirms the complete requested role. Cancellation and partial failure leave the guide unchanged. The helper preserves unrelated human content and refuses concurrent file replacement or edits. Agent instruction files and the project's existing `README.md` remain unchanged. Build tooling checks canonical bundle bytes and closure; the native installer handles host adaptation. Installer tests isolate native state so validation does not change user preferences.

The guide's source lives in `templates/HUMAN-README.md` in both the installation repository and packaged skills, with a dependency-free helper for writing it. Only the user's selected project receives a root `HUMAN-README.md`; the installation repository's root documentation is `README.md`. The human starts onboarding by sending a setup or join prompt to their agent; Project setup remains the canonical onboarding procedure. Direct skills CLI use still installs skill files, while the documented full-install command also creates the guide.
